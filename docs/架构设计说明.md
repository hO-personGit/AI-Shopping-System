# 架构设计说明（V2.0）

> 本文档面向面试与二次开发，梳理系统架构、关键设计与技术选型理由。

## 1. 总体架构

```text
┌─────────────────────────────────────────────────────────────┐
│ Vue2 前端 (8080/80)                                         │
│  用户端 / 后台管理 / AI智能导购(多轮对话+SSE打字机)           │
└───────────────┬─────────────────────────────────────────────┘
                │ HTTP /api/**（Axios 统一请求）
┌───────────────▼─────────────────────────────────────────────┐
│ SpringBoot 后端 (1234)                                       │
│ Controller → Service → Mapper(MyBatis-Plus)                 │
│ Spring Security + JWT 鉴权                                   │
│ Redis 分布式锁(防超卖) / Caffeine+Redis 两级缓存 / Swagger   │
│ AiService 调用 AI 微服务（业务网关，前端不直连 AI）           │
└───────┬───────────────────────┬─────────────────────────────┘
        │                       │
   MySQL(业务数据)          FastAPI AI 微服务 (8001)
                             ├─ 智能导购（多轮对话+混合检索+Agent）
                             ├─ 文案生成 / 销售分析
                             ├─ FAISS 向量库 / 问答缓存
                             └─ LLM Provider 适配层(mock/qwen/openai/zhipu)
```

**三层解耦的核心收益**：AI 能力全部收敛在 Python 微服务，更换大模型、升级向量库或新增 AI 功能都不影响 Java 后端与前端，可独立扩展与部署。

## 2. 关键设计

### 2.1 AI 智能导购链路（RAG + Agent）

```text
用户提问
  → ① 会话记忆（LRU+TTL，按 sessionId 维护最近 6 轮）
  → ② 问答缓存（同 session 同问题直接命中，降低 LLM 调用成本）
  → ③ 混合检索（FAISS 向量 + BM25 关键词多路召回 → RRF 融合 → 销量加权重排）
  → ④ Function Calling 工具决策（search_products / query_stock / get_top_selling）
  → ⑤ 大模型生成推荐（约束 Prompt 防幻觉，只基于候选数据作答）
  → ⑥ SSE 流式返回 + 结构化推荐列表
```

**面试可深挖点**：
- 为什么用混合检索？纯向量检索对精确关键词（品牌名、型号）召回弱，BM25 补足精确匹配；RRF 融合对多路分数量纲不敏感，实现简单稳定。
- 为什么加问答缓存？LLM 调用有延迟与成本，同 session 的高频追问（如"还有吗""库存呢"）可复用。
- 为什么 Function Calling？让模型在需要实时数据（库存/销量）时主动调工具，而不是靠训练记忆编造。

### 2.2 防超卖（Redis 分布式锁）

```text
支付下单 → 获取分布式锁 lock:order:pay:product:{id}
  ├─ SET NX EX（原子），value=requestId（唯一）
  ├─ 扣减库存 + 增加销量 + 更新订单状态（事务）
  └─ Lua 脚本校验 requestId 后释放锁
```

- 防死锁：锁带 TTL（10s）。
- 防误删：释放前校验 value，仅本人可删。
- 高可用兜底：Redis 不可用时降级 JVM 本地锁，保证演示环境可用。

### 2.3 两级缓存

| 层级 | 技术 | 场景 | 失效策略 |
|---|---|---|---|
| 一级 | Caffeine（本地） | 商品分页/详情热点数据 | 写入后 10min 过期 |
| 二级 | Redis（分布式） | 多实例共享缓存 | 写入后 10min 过期 |

切换：`spring.cache.type=caffeine`（默认）/ `redis`。

### 2.4 编码与工程规范

- 全库统一 UTF-8（修复了历史 GBK/UTF-8 混用导致的编译隐患）。
- Git 分支模型：`main`（稳定）+ `develop`（集成）+ `feature/*`（开发）。
- CI：GitHub Actions 三服务并行构建测试。

## 3. 目录与职责

| 模块 | 职责 | 技术 |

| `vue/` | 前端展示与交互 | Vue2 · Element UI · ECharts |

| `ai-service/` | AI 能力服务 | FastAPI · LangChain · FAISS |
