# 架构设计说明（V4.0）

> 本文档面向面试与二次开发，梳理系统架构、关键设计与技术选型理由。

## 1. 总体架构

```text
┌─────────────────────────────────────────────────────────────┐
│ Vue2 前端 (8080/80)                                         │
│  用户端 / 后台管理 / AI智能导购(多轮对话+SSE打字机)           │
└───────────────┬─────────────────────────────────────────────┘
                │ HTTP /api/**（Axios 统一请求）
┌───────────────▼─────────────────────────────────────────────┐
│ SpringBoot 后端 (1234)                                       │
│ Controller → Service → Mapper(MyBatis-Plus)                 │
│ Spring Security + JWT 鉴权                                   │
│ Redis 分布式锁(防超卖) / Redis 预扣库存 / Caffeine+Redis 缓存 │
│ 缓存三防(布隆过滤器/互斥锁/TTL抖动) / 订单状态机 / Swagger    │
│ RabbitMQ(下单削峰/延迟关单) / 本地消息表(可靠投递)            │
│ 限流(令牌桶) / 熔断(滑动窗口) / 降级兜底                      │
│ TraceId 全链路透传 + Micrometer 指标                          │
└───────┬──────────────────────┬──────────────────────────────┘
        │                      │
   MySQL(业务数据)          RabbitMQ(订单事件/延迟队列)
        │                      │
        │              FastAPI AI 微服务 (8001)
        │              ├─ 智能导购（多轮对话+混合检索+Rerank+Agent）
        │              ├─ 文案生成 / 销售分析
        │              ├─ FAISS / Milvus 向量库（可插拔）
        │              ├─ Rerank 语义精排(lexical/api)
        │              └─ RAG 评估闭环(RAGAS 风格)
        │
   Prometheus ── 采集后端指标 ── Grafana 看板 (9090/3000)
```

**三层解耦的核心收益**：AI 能力全部收敛在 Python 微服务，更换大模型、升级向量库或新增 AI 功能都不影响 Java 后端与前端，可独立扩展与部署；MQ、本地消息表与订单状态机让下单链路具备高并发吞吐与最终一致性；限流熔断降级与可观测性让系统具备生产级稳定性。

## 2. 关键设计

### 2.1 AI 智能导购链路（RAG + Rerank + Agent）

```text
用户提问
  → ① 会话记忆（LRU+TTL，按 sessionId 维护最近 6 轮）
  → ② 问答缓存（同 session 同问题直接命中，降低 LLM 调用成本）
  → ③ 混合检索（FAISS 向量 + BM25 关键词多路召回 → RRF 融合）
  → ④ Rerank 语义精排（lexical 无依赖 / api 接 bge-reranker，失败自动降级）
  → ⑤ Function Calling 工具决策（search_products / query_stock / get_top_selling）
  → ⑥ 大模型生成推荐（约束 Prompt 防幻觉，只基于候选数据作答）
  → ⑦ SSE 流式返回 + 结构化推荐列表
```

**评估闭环（RAGAS 风格）**：`python -m app.evaluation.run_eval --compare` 产出 `eval_report/eval_report.md`，
指标覆盖 recall@k / precision@k / hitRate@k / MRR / NDCG@k（检索）与忠实度 / 相关性代理指标（生成）。
评估数据集对齐真实商品库，实测精排相对基线 mrr +12.5%、ndcg@5 +9.65%。

**检索升级（v4.0）**：向量库可插拔，新增 `MilvusStore` 适配层（pymilvus 条件导入），
`VECTOR_DB=milvus` 时启用，连接/写入/检索失败自动降级 FAISS，检索链路不中断。

### 2.2 MQ 异步下单链路（削峰 + 最终一致性）

```text
下单请求
  → ① 校验商品 & Redis 预扣库存（Lua 原子：DECRBY + 不足回滚，防超卖）
  → ② 生成雪花订单号 order_no + requestId 幂等校验
  → ③ 业务事务内：订单落库 + 本地消息表登记 PENDING（同事务）
  → ④ 定时任务扫描 PENDING → 投递 RabbitMQ / 处理器幂等消费 → SENT
  → ⑤ 支付成功 → ORDER_PAY_SUCCESS → 状态 0→1 + DB 原子扣库存（WHERE stock>=qty）
  → ⑥ 超时未支付 → 延迟队列(TTL+DLX) → 状态 4 + 回补 Redis 预扣库存
  → ⑦ 投递失败指数退避重试（5/10/20/40/80s，5 次上限标记 FAILED）
```

**可靠性设计**：
- 消费者**手动 ACK + 幂等处理**（orderNo 唯一键 / 状态机判断），失败进死信队列。
- **本地消息表**与业务同事务，RabbitMQ 不可用时仍保证可靠最终一致性（实测 PENDING → SENT 12s 内完成）。
- 接口幂等：`@Idempotent` 按 requestId 幂等，重复下单直接返回首次结果。

### 2.3 订单状态机

```
0 待支付 ──支付──▶ 1 已支付 ──发货──▶ 2 已发货 ──确认收货──▶ 3 已完成
    │                │                    │
    └──超时/取消──▶ 4 已取消    └──申请退款──▶ 5 退款中 ──同意──▶ 6 已退款
                                                       └──拒绝──▶ 7 退款失败
```

- 状态流转由 `OrderStatus.canTransition(from, to)` 统一校验，非法流转（如待支付→已完成）直接拒绝。
- 状态变更均记录 `last_status`，支持退款、取消等回滚语义。

### 2.4 缓存三防（穿透 / 击穿 / 雪崩）

| 问题 | 防护手段 | 实现 |
|---|---|---|
| 穿透 | 布隆过滤器 + 空值短 TTL 缓存 | 自实现 `ProductBloomFilter` 拦截确定不存在的 key；空结果缓存 30s |
| 击穿 | 互斥锁 + 双检 | Redis 分布式锁 / JVM 本地锁串行化重建，双检避免重复打库 |
| 雪崩 | TTL 随机抖动 | 写入时 TTL 叠加 0~120s 随机值，错峰过期 |

- 两级缓存：Caffeine 一级（毫秒级）+ Redis 二级（多实例共享，可开关）。
- 商品写操作（增删改/状态）自动失效对应缓存。

### 2.5 防超卖（双层兜底）

- **下单层**：Redis Lua 原子预扣库存，并发下单快速拒绝超卖。
- **支付层**：分布式锁（SET NX EX + Lua 释放）串行化 + DB 原子 UPDATE（`WHERE stock >= quantity`）最终兜底。
- Redis 不可用：自动降级本地锁 / 同步校验，保证演示环境可用。

### 2.6 限流熔断降级（v4.0）

- **令牌桶限流** `@RateLimit`：容量突发 + 匀速补充 + 空闲回收，商品详情 200r/s / 下单 100r/s / AI 接口 20~50r/s，超限返回 429。
- **滑动窗口熔断** `@CircuitBreaker`：失败次数/失败率双阈值，闭/开/半开三态，熔断期返回 503。
- **AI 降级兜底**：AI 服务不可用时导购降级销量热榜、文案降级模板、销售分析降级本地统计（source=fallback），服务恢复后半开探测自动关闭。

### 2.7 可靠消息：雪花 ID + 幂等 + 本地消息表（v4.0）

- **雪花 ID** `SnowflakeIdGenerator`：41 位时间戳 + 5 位数据中心 + 5 位机器 + 12 位序列，时钟回拨检测，订单号全局唯一（实测 18 位纯数字）。
- **接口幂等** `@Idempotent` + Caffeine 幂等结果缓存：requestId 幂等键，重复下单返回首次结果。
- **本地消息表**：`message_record` 表 + `MessageReliabilityService`，订单落库与 PENDING 消息同事务，定时扫描投递 → 处理器幂等消费 → SENT，失败指数退避重试。

### 2.8 可观测性三件套（v4.0）

- **TraceId 全链路透传**：后端 `TraceIdFilter` 生成 16 位 hex，MDC 贯穿 Web → MQ 消息 → AI 微服务，日志格式 `[%X{traceId}]` 单请求可串联。
- **Micrometer 指标**：http_requests_total / duration（P50/P95/P99）/ status / path + Caffeine 命中率 Gauge。
- **Prometheus + Grafana**：`deploy/monitoring` 提供 prometheus.yml、数据源与 6 面板看板，docker-compose 一键拉起 9090/3000。

## 3. 目录与职责

| 模块 | 职责 | 技术 |
|---|---|---|
| `vue/` | 前端展示与交互 | Vue2 · Element UI · ECharts |
| `springboot/` | 业务后端 + AI 网关 + MQ 下单 + 可靠消息 | Spring Boot 3.4 · MyBatis-Plus · Redis · RabbitMQ |
| `ai-service/` | AI 能力服务 | FastAPI · LangChain · FAISS/Milvus · Rerank |
| `perf/` | 性能压测资产与实测数据 | JMeter · Python 压测脚本 |
| `deploy/` | 编排部署与监控 | docker-compose · K8s · Prometheus/Grafana |
